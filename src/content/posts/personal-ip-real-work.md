这几天，我和一个做云服务很多年的前辈谈了两次，前后六个小时左右。

聊的东西很散：云服务、AI、项目、学生市场、创业、自媒体、客户、咨询。

但回来以后重新整理，我发现这些话题最后都指向同一个问题：

> **一个刚开始做事情的人，究竟应该先抓什么？**

我以前没有完全想明白。

做自媒体，会先想涨粉；做项目，会先想能不能写进简历；帮别人解决问题，也会自然想到这件事以后能给自己带来什么。

这些想法本身没有错。

**错的是次序。**

## 01｜我过去把次序弄反了

一个人事情还没有做多少，别人也不知道你究竟能干什么，这时候如果天天研究怎么变现、怎么包装、怎么建立个人 IP，最后很容易碰到一个问题：

**没有足够真实的东西可以被包装。**

你可以在简介里写 AI、Agent、Builder，也可以写长期主义、独立思考。

但别人真正判断你，不是看这些词，而是看：

你做过什么？

你解决过什么问题？

遇到复杂事情的时候，你是怎么判断、怎么推进、怎么收尾的？

这也是这六个小时里，我最大的一个变化：

**先别急着定义自己，先把事情做出来。**

## 02｜信任和正式劳动，是两回事

他谈到维护客户时，有一个例子我印象很深。

今天一个学生可能只买 100 块钱的服务器，甚至什么都不买，只是来问你一个域名为什么打不开。

你帮不帮？

如果只算今天这一笔账，当然不划算。

半个小时解决一个问题，可能一分钱也没有。

但人的情况会变化。

学生会毕业，会工作；做小项目的人以后可能开始做真正的产品；今天只会问域名解析的人，几年以后也可能自己创业。

所以有些小问题，几分钟能解决，顺手帮一下，本质上是在积累信任。

但如果一个问题要花一天、两天，甚至需要长期维护，那就已经不是“顺手帮忙”了，而是正式劳动，应当重新谈边界和回报。

这两个东西不分清楚，都走不远。

一种是什么事情都想着马上收费。

另一种是什么事情都免费，最后自己一天到晚替别人干活。

> **真正要分清楚的是：什么是在积累信任，什么已经属于正式劳动。**

这句话对我影响很大。

## 03｜别先想项目，先找真的问题

我最近碰到的很多事情，其实都很小。

朋友的网站打不开，我去排查服务器和域名的问题。

域名解析不对，就去确认到底是哪一层出了问题。

朋友准备开宠物店，我开始从真实业务往回推：商品、库存、会员、预约、订单、退款这些事情，能不能被一套系统真正接住，而不是先决定“我要用什么高级技术”。

看到一个开源项目，我会先把它跑起来，看看它到底能不能用、边界在哪里，而不是只看 README 里的介绍。

我还在做一件更长期的事情：研究怎么把一本书整理成 AI 真正可以调用的知识结构。不是把 PDF 丢进向量库做一个问答框，而是继续拆原始内容、语义模型、机制和方法、作者的世界模型、文风和问答契约。

这些事情单独拿出来，都不算什么“大项目”。

但现在我越来越不嫌它们小。

**问题是真的，就值得研究。**

今天很多人做项目的顺序恰恰相反：

先问什么项目比较高级，什么技术写在简历里好看，再编一个需求把技术装进去。

最后项目看起来很完整，却没有一个真实的人真的需要它。

没有真实问题，技术就失去了落脚的地方。

所以我现在更愿意先问四个问题：

1. 身边的人现在到底有什么麻烦？
2. 这个问题是不是会反复出现？
3. 我能不能先用最简单的办法解决一次？
4. 解决以后，它有没有必要继续变成一个系统？

![先去做事：发现问题、研究、解决、写下来](/images/posts/personal-ip-real-work/process.webp)

*发现问题 → 研究 → 解决 → 写下来。先把真实问题做出来，再谈更大的系统。*

这套顺序对我来说，比“我要做一个什么 AI 项目”有用得多。

## 04｜自媒体暂时不是流量池，而是公开工作记录

我们也聊了很多自媒体、涨粉和变现。

但聊到最后，我反而觉得，对于现在的我来说，自媒体最有价值的地方暂时不是流量，而是**公开工作记录**。

今天研究了一个东西，就把结论写下来。

踩了一个坑，就把问题是什么、为什么会出错、最后怎么理解的写下来。

一个项目做失败了，也可以写为什么失败。

跟别人聊完以后，发现过去有个问题一直没想清楚，就回来继续查、继续做。

这样做首先对自己有用。

现在每天看到的信息太多。收藏一个链接、看完一篇帖子，很容易让人产生一种“我已经知道了”的感觉。

但过几天以后，往往什么都留不下来。

真正逼自己把一个东西写清楚时，问题才会暴露出来：

这个地方我真的懂了吗？

这个结论从哪里来的？

有没有证据？

我自己验证过没有？

写作在这里不是内容生产，而是一种检查。

它逼着我把浮在脑子表面的信息，变成自己能够解释、能够复用的东西。

其次，别人也会通过这些记录认识我。

不是因为我说“我会做 Agent”“我懂工程”“我是 Builder”，而是因为他真的能看到我做过什么。

> **简介只能声明能力，作品才能证明能力。**

这比在个人介绍里堆更多标签有用。

## 05｜项目、研究、写作，其实是一件事

以前我会把这些事情分开。

项目是项目。

学习是学习。

写文章是写文章。

自媒体又是另一件事。

现在我越来越觉得，它们其实可以是一条线：

**问题 → 研究 → 解决 → 复盘 → 公开 → 新问题**

做项目，是为了真正解决问题。

研究，是为了把问题弄清楚。

写东西，是为了把研究消化掉，同时把经验留下来。

自媒体，只是把这些东西公开出去的一个出口。

有人看完以后提出新的问题，我再去研究。

有人真的有这个需求，我就去做。

做完以后，又会产生新的判断和经验，可以继续记录。

这样一来，输出就不需要硬找选题。

因为内容不是凭空想出来的，而是从真正做过的事情里长出来的。

## 06｜个人 IP 不是先设计出来的

我以前理解个人 IP，多少还是带着一点“先设计一个形象”的思路。

我要让别人觉得我是一个什么样的人？

我要发什么内容？

我要贴哪些标签？

但现在我更愿意反过来看。

不是先有一个“个人 IP 计划”，然后到处寻找内容往里面填。

而是先做事情。

事情做多了，研究多了，留下的记录多了，一个人的判断方式、关注的问题、做事习惯自然会慢慢显出来。

这个东西比一句自我介绍更难伪造。

我现在才刚开始，做的事情也还很小。

这没有什么不好。

问题不在小，而在于是不是真的。

真的问题，一个一个解决。

真的东西，一点一点留下。

**我现在更想做的，是让每一篇文章、每一个项目，都成为一条可以被验证的记录。**
