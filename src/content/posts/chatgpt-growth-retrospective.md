## 2023 年下半年｜开始使用 ChatGPT

**状态：能追溯到的最早阶段**

目前能够比较明确追到：

> 你在数学建模相关学习 / 比赛阶段已经开始使用 ChatGPT。

当时 AI 的角色很简单：

```text
查知识
+
辅助分析
+
生成代码
+
解释报错
+
帮助数学建模
```

典型模式还是：

```text
我不会
→
问 ChatGPT
→
ChatGPT 给答案 / 代码
→
我拿去用
```

这时的 AI，本质上还是一个更强的学习助手。

还没有 Agent、Tool、Memory、Workflow、Eval、Harness 这些后来越来越重要的概念。

## 2025 年下半年｜第一次用 AI + Python 产生可量化生产力

**状态：真实落地成果**

工作里存在大量重复数据处理。

你没有一直手工做，而是开始用：

> **ChatGPT + Python**

写自动化脚本。

包括：

- 字段映射
- 格式转换
- 批量重命名
- 文件批处理

效果：

> 原来约 3 天的工作，被压缩到半天左右。

后来脚本不是只有你自己使用：

> **团队日均复用 10+ 次。**

按这个口径，大致相当于约 83% 的时间压缩。

这是整个成长路径里非常重要的一次变化：

```text
以前：AI 让我学习更快

后来：AI + 代码让一个团队的工作更快
```

第一次出现了非常明确的：

# 技术 → 生产力

**状态：已结束**

## 2026.05 下旬｜接触 Coding Agent——2026 年最大的转折点之一

**状态：方向转折**

你后来回忆：

> 2026 年 5 月底参加华为开发者大会相关活动时，偶然接触到了 Coding Agent。

以前用 ChatGPT 写代码大多是：

```text
提问
→
生成代码片段
→
复制
→
报错
→
继续问
```

Coding Agent 带来的变化是：

```text
给任务
→
Agent 读整个仓库
→
自己定位文件
→
直接修改
→
执行命令
→
跑测试
→
看 Diff
→
继续修
```

AI 第一次从：

> 聊天窗口里的代码助手

变成：

> **真正进入工程执行环节的 Agent。**

这之后，你开始持续折腾：

- Codex
- Claude Code
- OpenCode
- Cursor
- AtomCode
- Grok

你的关注点也逐渐变化：

> 不只是“模型回答得聪不聪明”，而是“它能不能稳定把仓库里的活做完”。

## 2026.06 初｜开始研究 Agent 本身

**状态：认知转折**

你开始问一些以前不会问的问题：

- Agent 到底由什么组成？
- Tool 在哪里？
- Planner 怎么工作？
- Memory 放在哪里？
- Workflow 怎么控制？
- Harness 是什么？
- 怎么做 Evaluation？
- Agent → Agent 的能力复刻有没有可能？
- “蒸馏模型”和“复制 Agent 能力”到底是不是一回事？

关注对象从：

> LangChain 怎么调用

变成：

> **一个 Agent 的能力究竟存在哪里。**

这个问题后来几乎贯穿：

- Book Voice
- Skill
- Context Engine
- Personal OS
- 多 Agent 协同

## 2026.07 中旬｜Excel 对账 Agent：第一次认真解决“AI 做错怎么办”

**状态：阶段性完成**

这个项目里开始出现后来反复使用的工程思想：

- 状态机
- Tool Contract
- 人工审批
- 审计
- 异常预览
- 报告导出
- 自动测试
- 源文件保护

阶段性做到了：

> **6 / 6 核心测试通过，并完成前端生产构建。**

测试里会考虑：

- 恶意单元格
- 非法状态转换
- Schema 缺失
- 源文件被误改

这个节点非常关键。

你的问题第一次从：

> AI 能不能把任务做出来？

变成：

> **AI 做错了，系统有没有能力拦住？**

这是从普通 AI 应用走向 Agent Engineering 的分界线之一。

# 几条比技术栈更重要的成长线

## 1. 从“找更强的工具”到“设计更好的工作流”

早期容易问：

> 哪个模型更强？

> 有没有新的 Agent？

> 有没有更好的 Skill？

现在仍然会研究工具，但开始问：

> 它到底解决我工作流里的哪一个瓶颈？

> 它和 Codex / Cursor / Claude Code 怎么分工？

> 是真正需要，还是只是再堆一个工具？

最后真正留下来的越来越是：

```text
Context
+
Task Boundary
+
State
+
Verification
+
Review
+
Governance
```

---

## 2. 从“做完一个项目”到“把经验沉淀下来”

以前：

```text
做完
→
下一个
```

现在：

```text
做项目
↓
踩坑
↓
复盘
↓
抽规则
↓
写进 ADR / AGENTS.md / SOP / Skill / Blog
↓
下一个项目默认复用
```

例如：

- PetStore → 多 Agent SOP / Repo Identity Gate / 状态机；
- UI → 组件分层与复用规则；
- Book Voice → Factory / Contract / Validator / Eval；
- 内容生产 → Harness / 不虚构规则；
- Personal OS → Event / Memory / Permission / 人工确认。

你开始形成的，不只是经验。

而是：

> **自己的工程方法论。**

---

## 3. 从“做得完整”到“有没有真实的人用”

7 月以后你越来越警惕：

```text
项目做得很完整
↓
但没有用户
```

开始把价值判断放到：

- 真实需求
- 真实使用
- 真实反馈
- 真实数据
- 是否愿意继续用
- 是否愿意付费

这对你以后做独立开发非常关键。

---

## 4. 从“简历写得厉害”到“事实必须经得住追问”

你越来越主动纠正：

- 不是自己做的不能算自己
- 队友提供的 API 不能写成自己开发
- 方案项目不能包装成完整运行系统
- 技术栈必须对应真实贡献
- 证书、奖项和描述不能随便错

这形成一个很重要的职业习惯：

> **表达可以优化，事实不能优化。**

---

## 5. 从“项目能运行”到“系统能不能长期不失控”

以前成功标准可能是：

> 页面出来了，功能能点。

现在会继续检查：

- 测试过了吗？
- PR Merge 了吗？
- HEAD 对吗？
- changed files 有没有越界？
- CI 是绿的吗？
- 文档和代码一致吗？
- 哪个是真值？
- 下一步是否允许开始？

这就是大型项目经验真正开始形成的地方。

# 最后，把三年压缩成几个问题

2023 年：

> **AI 能不能帮我把这个问题做出来？**

2024 年：

> **我能不能用代码把一个现实问题算出来？**

2025 年：

> **AI 能不能帮我做产品、帮团队真正提高效率？**

2026 年 5～6 月：

> **Coding Agent 为什么能自己完成工程任务？Agent 的能力到底在哪里？**

2026 年 7 月：

> **怎么把 Agent 真正交付出去？AI 做错了怎么办？**

2026 年 8 月：

> **知识、方法、风格、记忆能不能保存成长期可调用的结构？我自己的生活能不能也被系统化？**

2026 年 9 月：

> **怎么让多个 Coding Agent 在一个大型项目里长期工作，而项目不会失控？**

所以真正的成长路径是：

```text
使用 AI
↓
利用 AI
↓
产品化 AI
↓
理解 Agent
↓
构建 Agent
↓
约束和验证 Agent
↓
管理多个 Agent
↓
设计 AI 的工作方式
```

最早，你更像：

> **一个学计算机、会用 ChatGPT 的学生。**

后来变成：

> **一个会用 AI 写代码、做项目的人。**

再后来变成：

> **一个在做 AI Agent 工程的人。**

而现在正在往：

> **“我设计一套系统，让人和多个 AI 一起把复杂事情做完。”**

这个方向走。

如果未来几年再回头看，**2026 年 5 月到 9 月**很可能会是一条非常清楚的分界线。

因为就在这几个月里，AI 对你的意义从：

> **一个聊天工具**

逐渐变成：

> **一种新的工程组织方式。**
